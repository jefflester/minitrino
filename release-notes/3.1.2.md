# Minitrino Release Notes: 3.1.2

## Release Overview

Minitrino 3.1.2 is a maintenance release that updates dependencies and fixes
the release smoke test, which was reporting false passes.

**Key improvements:**

- Updated `click` to 8.5.0 and `docker` to 7.2.0
- Updated GitHub Actions to their latest major versions
- Fixed the release smoke test so provisioning failures are detected, and fixed
  Docker Compose and Buildx setup on macOS runners

## Library Changes and Additions

### Reduced Memory Usage of `cache-service` Example Materialized View

The `example` materialized view created by the `cache-service` module selected
500 rows per branch of a `UNION ALL` while partitioning by `orderdate`, creating
a partition (and ORC writer) for nearly every row. Its refresh used roughly 80%
of the default per-node query memory limit and could exceed it, causing the
refresh to fail. The view now selects 50 rows per branch, reducing peak refresh
memory from ~480 MB to ~57 MB.

## Other

### CI/CD: Smoke Test False Passes

The provision step of the release smoke test captured the exit code of `tee`
rather than `minitrino provision`, so it always passed. This masked a real
failure on macOS runners, where Homebrew's `docker` formula does not include the
Docker Compose v2 or Buildx plugins.

**The fix:**

- The provision step now uses `PIPESTATUS` to capture the correct exit code
- The macOS runner installs and registers the `docker-compose` and
  `docker-buildx` plugins
- A new step verifies Docker, `docker compose`, and `docker buildx` before
  provisioning
- Colima startup on macOS is bounded to 8 minutes per attempt and retried once
  from a clean VM, and the job has a 35-minute timeout, so a hung runner fails
  quickly instead of blocking the release gate

### CI/CD: Reusable Smoke Test Workflow

The smoke test has moved from `release.yaml` into a reusable `smoke-test.yaml`
workflow. It still gates the release, and can now also be run:

- Manually via `workflow_dispatch` against any published version
- Automatically on pull requests that modify `smoke-test.yaml`, against the
  latest published version

### CI/CD: Build Test Images When Fallback Images Are Missing

When a PR does not change image-related files, CI skips building test images
and pulls `latest-trino` and `latest-starburst` from GHCR instead. No workflow
publishes those images, so they were missing and every test job failed during
setup. Change detection now builds the test images whenever those fallback
images cannot be resolved.

### CI/CD: macOS Runner Update

The macOS smoke test now runs on `macos-15-intel`. The previous `macos-13`
runner image was retired by GitHub, which caused the job to queue indefinitely.

### CI/CD: GitHub Actions Updates

- `actions/checkout`: `v6` → `v7`
- `actions/setup-python`: `v6` → `v7`
- `actions/setup-java`: `v4` → `v5`
- `actions/cache`: `v4` → `v6`
